# M11b: Dashboard redesign (Swiss)

## What was built

The M11 dashboard redrawn in the International Typographic Style, with no change to what
it does or to the API. The engineering underneath (market-data client, integer prices,
key storage, the shared fixtures) is untouched; what changed is the look, the words and
how terms are explained.

- **One visual system** (`dashboard/src/styles/app.css`, rewritten): white background,
  `#111` text, one self-hosted grotesk (Hanken Grotesk via `@fontsource`), a strict
  12-column grid set flush left, hierarchy from type size and 2–3 px black rules, numbered
  section labels (`01 Order book`). No rounded corners, shadows, cards, gradients or emoji.
  Monospace only inside "Show technical details".
- **Overview as a poster**: one very large throughput number, then numbered rows
  (Engine, Correctness, Backtest, Architecture), the architecture redrawn in black lines.
  Every number still comes from the results files at build time.
- **Live market**: the book takes 8 columns with the order form and trades beside it, a
  very large last price, a thin black status bar. Missing book levels are blank space,
  not empty rows, so the spread stays in the middle of the panel.
- **Color with one meaning each**: green `#007A33` = buy, red `#E3001B` = sell or error,
  gold `#B08D1F` = emphasis, only as a line or fill (active nav, section numbers, tour
  outline, the Live dot, Try trading hover). The words Buy and Sell are always there.
- **Terms instead of ⓘ icons**: `src/components/Term.tsx`, a dotted-underline button with
  a tooltip; definitions in `copy.ts` and on a new Glossary page. A new About page and a
  footer ("Built by Ovunda Aguma", GitHub, About, Glossary).
- **All words in one file**: `src/copy.ts` holds every user-visible sentence, including
  the messages the `lib/` modules build (order summaries, input errors, run summaries,
  form errors). Reject messages stay in `content/rejects.json` and are re-exported.
- **Charts**: net solid black, gross dashed grey; square bars; drawn at measured width.
- **Removed**: the old design-preview fonts (Inter, IBM Plex, JetBrains Mono),
  `Info.tsx`, `content/glossary.ts`.

## Read these first

1. `dashboard/src/copy.ts`: every sentence, grouped by page; functions where a sentence
   takes values.
2. `dashboard/src/styles/app.css`, the `:root` block: every color and size token.
3. `dashboard/src/components/Term.tsx`: hover, focus, tap and dismissal in ~80 lines.
4. `dashboard/src/lib/copy.test.ts` and `contrast.test.ts`: the two rules the design
   depends on, enforced.
5. `dashboard/src/components/Ladder.tsx`: the spacer rows that keep the spread centered.

## Design decisions

- **Swiss style for a trading tool.** The content is numbers and short labels; a grid,
  one typeface and size contrast make the hierarchy obvious without decoration, and a
  white page prints and screenshots cleanly. Rules instead of cards keep density high
  without boxes inside boxes.
- **Hanken Grotesk, not Schibsted.** The plan named Schibsted Grotesk; in testing its
  `tnum` feature also widened `, . : ; # %`, so prices like `42.15` looked loose. Hanken's
  default digits are already tabular and its punctuation stays narrow, so columns of
  prices align with no feature flags.
- **One meaning per color.** Red first stood for brand accent and sell. Once buys were
  green, red on the Live dot read as "something is wrong", so the dot became gold and red
  is now only sell or error. Gold fails AA as text (it is 3.1:1 on white), so it is used
  only for lines and fills, where 3:1 is the requirement; a test forbids `color:
  var(--gold)`.
- **Focus ring in black, not red.** A red ring would read as an error on every Tab. A 2 px
  `#111` outline with a 2 px offset is visible on white and turns white on the black
  status bar.
- **Terms instead of icons.** An ⓘ after every label adds noise and a tiny target. A
  dotted underline on the word itself is a larger target and says "this word is defined".
  Tooltips must work on touch: a tap pins it, a tap elsewhere or Esc closes it (a
  Playwright test at 390 px with touch enabled).
- **Copy in one file, enforced by a syntax-tree test.** A grep would flag class names and
  URLs; the TypeScript parser knows a JSX text node from a `className` string. Messages
  for programmers (`new Error(...)`) are exempt: they describe a bug, not a person's
  mistake. The test checks itself on small examples so a regression in the walker cannot
  pass silently.
- **Charts at measured width.** A fixed `viewBox` scaled down to 358 px drew 5 px axis
  text on phones. A `ResizeObserver` gives the SVG its real width, so text is always its
  CSS size and the year labels thin out by available space.

## Trade-offs and what was left out

- **No dark mode.** The brief is white-on-black type; a dark theme would be a second
  design to keep accessible. The tokens are on `:root`, so adding one is a token swap.
- **Grey chart pair.** The dataviz validator flags `#111`/`#767676` on lightness band and
  chroma floor (it expects colored series). It passes colorblind and normal-vision
  separation (ΔE 38.8) and contrast, and gross is also dashed, so identity never rests on
  color alone. Color is reserved for buy, sell and error.
- **Wide tables scroll on phones.** The runs table keeps its six columns and scrolls
  inside its own box at 390 px; the page itself never scrolls sideways.
- **Copy is English only.** One file makes translation possible later; no i18n framework.

## Interview questions

1. *Why can't the gold be used for text?* It is 3.1:1 against white; WCAG AA needs 4.5:1
   for body text but only 3:1 for graphical objects, so it is used for rules and fills,
   and `#111` text on a gold fill is 6:1. A test reads the tokens and checks both.
2. *How do you keep every sentence in copy.ts?* A Vitest test parses each source file
   with the TypeScript compiler API and reports JSX text with letters, readable attributes
   with words, and string literals that look like phrases, ignoring `className`, URLs and
   developer errors.
3. *How does a tooltip work with mouse, keyboard and touch at once?* Hover and
   focus-visible show it; a click or tap toggles a pinned state; a `pointerdown` outside
   or Esc clears it; the tooltip is clamped to the viewport and linked by
   `aria-describedby`.
4. *Why does the book use spacer rows instead of empty rows?* Empty rows looked like
   levels with zero size. A spacer sized to the missing levels keeps the spread in the
   middle and the panel's height constant without drawing anything.
5. *What stayed exactly the same?* Every behavior: tests that assert sentences
   (order summaries, the "Try 41.99 or 42.00" hint, the run summary) passed unchanged
   because the text moved verbatim into copy.ts; e2e only changed where a word did
   ("Next", "Bought", the Spread term).
