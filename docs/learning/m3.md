# Milestone 3: Order types

Commit `0e89034`. Done when the Python reference engine and the differential test
agree on 1M random commands.

## What was built

**Engine**

- Market orders (must be IOC, `price == 0`), IOC, FOK, post-only (GTC limit only).
- Cancel-replace (`Replace`) keeping the `order_id`, with priority rules.
- Self-trade prevention per order: cancel-newest (default), cancel-oldest,
  cancel-both.
- `Cancelled` gains a reason (`USER`, `UNFILLED`, `SELF_TRADE`); a new `Replaced`
  event; four new reject reasons (`NO_LIQUIDITY`, `FOK_NOT_FILLABLE`,
  `POST_ONLY_WOULD_CROSS`, `REPLACE_QTY_TOO_LOW`) plus `INVALID_ORDER_TYPE`.

**Testing**

- A canonical text format for commands and events (`docs/event-format.md`), and
  `mf_driver`, which runs a command file through one book.
- `reference/`: a deliberately naive Python book, a seeded command generator and a
  streaming difftest harness.
- 12 golden scenarios with hand-derived expected output, run against both engines.
- pytest runs the difftest on 100k commands (also in CI); `make difftest-long` runs
  1M; failing cases are saved to `tests/difftest/regressions/` and replayed.

## Read first

1. `docs/order-types.md`: the rules, in prose and tables. Read this before the code.
2. `engine/src/order_book.cpp`:
   - `on_new_order` — the fixed validation order, then `Ack`, then `execute`.
   - `execute` — match, then cancel the remainder (STP or non-GTC) or rest it.
   - `match` — the sweep with STP checked maker by maker.
   - `fok_fillable` — the read-only mirror of `match`.
   - `on_replace` — the three replace cases.
3. `reference/book.py`: the same rules re-derived from a flat list and sorts.
4. `docs/event-format.md` and `engine/src/text_format.cpp`: the shared format.
5. `reference/difftest.py` (`difftest`, `_compare`, `save_regression`) and
   `reference/generator.py`.
6. `engine/tests/golden/*.cmds` / `*.events`: each rule as a concrete stream.

## Design decisions

- **Reject vs. Ack + Cancel.** "Reject when the order's contract can't be honored;
  Ack + Cancel when the outcome is within its contract." A market order into an empty
  side, an unfillable FOK and a crossing post-only are rejects (book untouched). An
  IOC that finds nothing was honored — "fill what you can" includes nothing — so it is
  acked and cancelled `UNFILLED`. One rule decides every edge case.
- **Fixed validation order** (price, qty, type combination, duplicate id,
  type-specific). Two engines must report the *same* first failure, so the order is
  part of the spec, not an implementation detail.
- **`Aggressor` struct.** A new order and a re-priced resting order are both "the
  incoming side", so `match`/`execute` handle both; replace reuses all the matching
  code, keeping the order's id, filled quantity and STP mode.
- **FOK by read-only pre-check.** `fok_fillable` walks the opposite side without
  mutating it, then the normal sweep runs. The alternative (match then roll back)
  would need undo logic and could emit events that must be retracted. The walk must
  mirror STP exactly: own orders are skipped under cancel-oldest and end the walk
  otherwise, so a FOK never partially fills and a rejected FOK never cancels the
  account's own resting orders.
- **Post-only rejects instead of re-pricing.** The spec allows either; rejection is
  simpler and has no hidden price choice. Crossing is judged against the book,
  including the account's own orders.
- **Replace semantics.** `qty` is the new *total* including fills (as in FIX), so
  `qty <= filled` is rejected. Same price and qty down or unchanged keeps priority
  (a no-op modify never costs priority); qty up moves to the back; a price change is
  cancel + new and may trade.
- **STP: the incoming order's mode decides, checked maker by maker.** The gateway
  fills the mode in from account config, so the command journal alone determines
  behavior. Fills before the self-match stand. The resting order is cancelled in full,
  not decremented.
- **Differential testing against an "obviously correct" reference.** The Python book
  uses a flat list and sorts by `(price, priority)` with no levels, links or index,
  so it shares no structure (and so few bugs) with the C++ book.
- **Generate the command file once, feed both engines.** RNG differences between
  languages cannot matter, and the file is the reproducer.
- **`BOOK` line after every command, `LVL` dump at the end.** Written by the drivers,
  not the engine. A divergence in book state shows up at the exact command that caused
  it, not thousands of commands later.
- **Streaming comparison, minimized regressions.** 1M commands are compared line by
  line without holding both outputs; on mismatch the harness prints seed, `seq_no`,
  command and context, and saves commands up to that `seq_no`. Saved files are
  replayed by pytest and stay valid even if the generator changes.
- **Golden files are hand-derived.** Two engines agreeing could mean both are wrong;
  goldens check each against an independently worked answer.
- **Generator biased toward interesting cases:** prices within ±8 ticks of the mid,
  only 4 accounts (frequent self-trades), occasional whole-side sweeps (empty-side
  market orders), invalid orders, and cancels of old orders to keep the reference's
  linear scans fast.

## Trade-offs and what was left out

- **No DAY time-in-force**: it needs session states (M4).
- **No post-only re-pricing**, no stop/stop-limit or iceberg (stretch goals).
- **STP decrement mode** not implemented; only full cancel of the resting order.
- **CI runs 100k commands, not 1M**, to keep CI fast; the 1M run is
  `make difftest-long`.
- **Hot-path allocation still present** (see M2); the text format and driver are test
  tooling, not on the hot path.
- **Duplicate-id check is still resting-only**; session-wide uniqueness is the
  sequencer's job (M4).
- The reference is slow by design (linear scans); the generator keeps its book small
  rather than making the reference clever.

## Interview questions

1. **How do you implement FOK without partial fills leaking out?**
   A read-only pass over the opposite side, in priority order and within the limit,
   sums the quantity the sweep would actually get, accounting for self-trade
   prevention. If it is short, reject before any state changes; otherwise run the
   normal sweep, which is now guaranteed to fill completely.
2. **When does a cancel-replace keep time priority?**
   Only at the same price with the total quantity down or unchanged. A quantity
   increase would let an order jump ahead with size it never queued for; a price
   change is a new order at a new level, so it goes to the back (and may trade).
3. **Why both golden tests and a differential test?**
   Goldens check against hand-derived answers, so they catch shared misreadings of a
   rule, but cover few cases. The difftest covers millions of random interleavings but
   only checks that two engines agree. Together they cover depth and breadth.
4. **How do you debug a difftest failure on command 700,000?**
   The `BOOK` line after every command localizes the first divergent command; the
   harness prints its `seq_no`, the command and preceding output, and saves the
   prefix as a regression file that `make difftest-replay` and pytest rerun.
5. **Why is a market order into an empty book a reject but an unfilled IOC a cancel?**
   A reject means the order's contract could never be honored and the order was never
   accepted. An IOC promises "fill what you can, cancel the rest"; filling nothing is
   a valid outcome, so it is acked and its remainder cancelled with reason `UNFILLED`.
